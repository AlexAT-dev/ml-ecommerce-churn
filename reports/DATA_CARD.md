# Data Card — ChurnGuard (прогноз відтоку клієнтів e-commerce)

Формат — Data Cards (Pushkarna et al., 2022). Версія даних — DVC-знімок **`lab3-v1.0`** (git-тег) + стадія `lab4a_split`.

## 1. Огляд

| | |
|---|---|
| Призначення | навчання й оцінювання моделі ризику відтоку для менеджерів з утримання (система підтримки рішень) |
| Одиниця спостереження | клієнт онлайн-рітейлера (один рядок = клієнт) |
| Ціль | `Churn` (1 — клієнт пішов), частка 16.6% |
| Ознаки | 16 полів запиту API (поведінка за останній місяць, стаж, категорії) + похідні (ЛР2) |
| Захищені ознаки | `CityTier` (основна), `Gender` — **зберігаються лише для аудиту**, у модель і в запит API не подаються |
| Ліцензія / доступ | Kaggle-набір (див. §2); у git — лише DVC-покажчики, самі дані — ні |

## 2. Походження і умови збору

| Джерело | Опис |
|---|---|
| Табличні дані | Kaggle «[Ecommerce Customer Churn Analysis and Prediction](https://www.kaggle.com/datasets/ankitverma2010/ecommerce-customer-churn-analysis-and-prediction)» (Ankit Verma, 2021): `E Commerce Dataset.xlsx`, аркуш `E Comm`, 5 630 × 20. Анонімна онлайн-компанія, імовірно Індія (UPI, COD, Tier-поділ міст); дата збору не задокументована («знімок за останній місяць»). |
| Корпус (ЛР2) | Amazon Reviews 2023 (McAuley Lab) — **у сервісі не використовується** (прив'язка до клієнтів була імітаційною, ознаки неінформативні, у CRM на момент запиту недоступні). |

**DVC-хеші:** сирий файл `data/raw/E Commerce Dataset.xlsx.dvc` → md5 `3586e9c1cb117a645b062deae6a961c2`;

## 3. Лінідж raw → features

```
E Commerce Dataset.xlsx (DVC)
  → дедуплікація: 556 точних копій прибрано → 5 074                        [src/data.py, ЛР2]
  → MCAR-пропуски (seed 42): CashbackAmount 20%, PreferedOrderCat 15%       [config/data.yaml, ЛР1]
  → стадія DVC prepare: розбиття 80/20 → train.csv (4 059) / holdout.csv (1 015)   [src/prepare_data.py, ЛР3]
  → стадія DVC lab4a_split: train.csv → pool (3 044) / test ЛР4A (1 015)    [src/run_lab4a.py, ЛР4A]
ЛР5:
  train v1      = train.csv @ lab3-v1.0, role = pool                       3 044 (відтік 16.6%)
  пул розмітки  = train.csv @ lab3-v1.0, role = test (відкладено до етапу 1)  1 015
  test ЛР5      = holdout.csv @ lab3-v1.0 (у ЛР3–ЛР4 не використовувався)    1 015 (відтік 16.6%)
Сервіс (поза ONNX): поля запиту → 64 клієнтські DFS-ознаки (a/b, log a) → препроцесор ЛР1–3 → SelectKBest → 15 ознак [src/serving]
```

## 4. Анотування (звідки мітки)

* **Мітка `Churn`** — прапорець компанії у вихідному наборі; процес визначення відтоку (через скільки днів неактивності) не задокументовано.
  Конфліктних міток серед дублікатів немає.
* **Labeling functions не використовувались.**
* **Раунд дорозмітки ЛР5 (трек 4A) — симульований.** Пул (1 015 клієнтів) пропущено через `/v1/predict` без міток. Черга розмітки:
  20 найменш певних запитів за стратегією **entropy + diversity** (ЛР4A), без запитів з фідбеком і без OOD.
  «Експерт» — **оракул**: справжні приховані мітки `Churn` пулу (`data/processed/pool_oracle.csv`, не в git), надіслані через
  `/v1/feedback`. Рівень згоди анотаторів не застосовний (один симульований анотатор, без помилок). **Бюджет — 20 міток.**
  Реальний анотатор помилявся б і мав би вартість — це обмеження симуляції.

## 5. Репрезентативність, сліпі зони, виключені підгрупи

* **Популяція:** клієнти одного рітейлера на момент знімка; перенесення на інші ринки чи компанії не обґрунтоване.
* **Мала група:** CityTier 2 — 4% клієнтів (у test 32 особи, 7 відтоків) — метрики для неї статистично ненадійні.
* **Пропуски не випадкові:** у `Tenure` 8.7% серед тих, хто пішов, проти 4.0% серед решти (MAR/MNAR) — індикатори пропусків стали ознаками моделі.
* **Синоніми категорій** (`Phone`≡`Mobile Phone`, `CC`≡`Credit Card`, `COD`≡`Cash on Delivery`) зведено за назвами, без підтвердження власника даних.
* **Виключено:** 556 дублікатів (4a REFORMS). Жодних підгруп свідомо не виключено.
* **Сліпі зони:** нові типи клієнтів поза діапазонами train (наприклад, дуже великі обсяги замовлень) — їх ловить OOD-детектор і передає правилу (0.1% test).
